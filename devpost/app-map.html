cveq — Application Map

Proof of Concept Snapshot • Commit 355783f

cveq is a fast, zero-dependency Node.js CLI triage tool for cybersecurity students, CTF players, and pentesters. It aggregates authoritative vulnerability records from CVE.org and top public Proof-of-Concept exploits from GitHub, formatting everything into an ANSI-colored terminal report and managing an Obsidian-compatible research journal.

Architecture Overview

The entire application runs natively on Node.js 18+ with zero third-party runtime dependencies. The flow of data is strictly deterministic, concurrent, and non-blocking:

  • CLI Dispatch: bin/cveq.js parses arguments, flags (--save, --help), and commands (journal).
  • Validation: src/utils/validator.js enforces ^CVE-\d{4}-\d{4,}$ and normalizes loose inputs (e.g. 2024-21762).
  • Concurrent Ingestion: src/api/cve.js (CVE.org) and src/api/github.js (GitHub Search API) fetch concurrently via Promise.all() with 8s timeouts.
  • Rendering: src/formatters/report.js wraps text and applies TTY-safe ANSI severity badges.
  • Persistence: src/journal/manager.js prepends newest entries directly under the header in ~/.cveq/journal.md.

To Change This, Start Here

  • Change output formatting or colors: Edit src/formatters/ansi.js (ANSI codes & TTY guards) and src/formatters/report.js (layout structure and wrapping).
  • Adjust API timeouts or upstream queries: Edit DEFAULT_TIMEOUT_MS in src/api/cve.js and src/api/github.js.
  • Customize Journal layout or Obsidian tags: Edit formatEntryMarkdown() in src/journal/manager.js.
  • Adjust CLI arguments or add new flags: Edit bin/cveq.js and update help functions.

A Practice to Reuse: Plan-First Boundary & Tolerant Contract Specification

During the planning phase (3-prd and 4-spec), we explicitly established two critical failure modes before writing code:

  1. Degraded GitHub 403 Rate Limits: Instead of treating an unauthenticated rate limit as a fatal CLI crash, the spec defined a partial success contract (render full CVE metadata, show friendly hint, exit 0).
  2. Tolerant Journal Markdown Ingestion: Because markdown files can be edited by humans in Obsidian, the spec established an amendment requiring regex parsers to tolerate missing fields and dashed heading variations without crashing.

Reusable Lesson: When building CLI tools that interact with third-party rate-limited APIs or local markdown files, specifying your degraded states and fault-tolerant parsing rules in your spec before code eliminates brittle edge cases and avoids rework during implementation.
